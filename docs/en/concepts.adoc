== Concepts

The format provides traffic state information obtained from floating car data (FCD) on a set of predefined
sections of the road network (segments): travel times, traffic speed, traffic status and level of traffic,
and an estimate of the length and position of queues. Speeds are provided for all vehicles together and
separately for cars and lorries; travel times, traffic status, level of traffic and queues for all vehicles
only.

The format is based on the DATEX II `roa:ElaboratedDataPublication` <<EN16157-5>>. Levels of traffic as used
in the Czech Republic and queues are added by the *NDIC extension* (a backward-compatible extension placed in the extension point
`_trafficStatusExtension` of `roa:TrafficStatus`). It uses the DATEX II 3.7 model; data quality and the number of vehicles are carried by
native attributes of the model.

[[obalka]]
=== Envelope and publication header

Each message is a DATEX II 3 document with the root element `d2:payload`. The `@xsi:type` attribute of the
root element determines the publication type (here `roa:ElaboratedDataPublication`), the attribute
`modelBaseVersion="3"` the model version and the attribute `@lang` the default language of texts.

The format according to which the message is built is identified solely by attributes of the root element:

[horizontal]
`@profileName`:: format identifier without version (`cz-ndic_d2-fcd-status`),
`@profileVersion`:: format version (`2.0`).
`@extensionName`, `@extensionVersion`:: NDIC extension used in the message (`cz-ndic_d2-fcd-extension`, `1.0`).

The publication header contains:

* `feedType` – identifier of the data source the message comes from:
** the format of the message is identified by the `@profileName` and `@profileVersion` attributes, not by
   `feedType`,
** the `feedDescription` element is not used.
* `publicationTime` – time the publication content was created; if the content has not changed since the
  previous publication, the original time is kept; a new time is set only when the content changes.
* `publicationCreator` – publisher:
** country code in lower case (`cz`),
** the publisher's abbreviation (`nationalIdentifier`), always `NDIC`.
* `headerInformation` – handling of the information; NDIC always states:
** `confidentiality` = `noRestriction`,
** `informationStatus` = `real`.

All time values in the message include the time zone.

[[struktura]]
=== Publication structure

Each value for one segment and one vehicle type is a separate element `physicalQuantity` of type
`roa:SinglePhysicalQuantity`. It contains the reference to the segment location (`pertinentLocation`) and
the value itself, `basicData`, of one of the types:

[cols="2,4",options="header"]
|===
|`basicData` type |Content
|`roa:TrafficStatus` |traffic status (`trafficStatus`) and, in the NDIC extension, level of traffic and queues – for all vehicles only
|`roa:TrafficSpeed` |current average speed of the traffic flow (`averageVehicleSpeed`) [km/h]
|`roa:TravelTimeData` |current travel time (`travelTime`), free-flow travel time (`freeFlowTravelTime`),
delay (`travelTimeDelay`) [s] and free-flow speed (`freeFlowSpeed`) [km/h]
|===

A segment with a mixed traffic flow therefore has three `physicalQuantity` elements. Segments where speed
and travel time are evaluated separately by vehicle type have up to seven (traffic status for all vehicles,
speed and `roa:TravelTimeData` for `anyVehicle`, `car` and `lorry`), depending on whether vehicles of the given type
were present on the segment during the evaluation. The element `physicalQuantity` has no identifier of its
own; it is uniquely determined by the publication time, the referenced location, the `basicData` type and
the vehicle type.

[[kategorie]]
==== Vehicle categories

Scope of information by segment:

* Segments with a *mixed traffic flow* (vehicles travel together, e.g. in one lane) carry information for
  all vehicles only (`anyVehicle`).
* Segments with a *separated traffic flow* (several lanes where speeds of cars and lorries differ)
  additionally carry for cars (`car`) and lorries (`lorry`):
** the current speed (`roa:TrafficSpeed`),
** the free-flow speed (`roa:TravelTimeData` with `freeFlowSpeed` only).
* For all vehicles only:
** travel time, free-flow travel time and delay,
** traffic status, level of traffic and queues (`roa:TrafficStatus` states no vehicle type).

The vehicle type is given:

* in `roa:TrafficSpeed` in `forVehiclesWithCharacteristicsOf/vehicleType`,
* in `roa:TravelTimeData` directly in `vehicleType`.

[[kvalita]]
==== Data quality and number of vehicles

Calculated values carry attributes of the model (class `com:DataValue`):

* `@supplierCalculatedDataQuality` – reliability of the value in per cent:
** 0–100, 100 = fully reliable,
** assessed from the age and amount of the probe vehicle data used,
** the formula is not part of the format.
* `@numberOfInputValuesUsed` – number of floating vehicles the value was calculated from.

Values for all vehicles (`trafficStatus`, `averageVehicleSpeed`, `travelTime`) carry both attributes, speeds
of cars and lorries only `@numberOfInputValuesUsed`. Values not depending on current vehicles (statistical
`freeFlowSpeed`, `freeFlowTravelTime`) carry no quality attributes.

[[stav]]
=== Traffic status

The traffic status is a value of the enumeration `roa:TrafficStatusEnum` according to the definitions of the
3.7 model, determined from the ratio of the current speed to the free-flow speed:

[cols="1,2,1",options="header"]
|===
|Value |Meaning |Speed ratio
|`stationary` |stationary traffic |< 10 %
|`queuing` |queues, stop-and-go traffic |10 % or more, less than 25 %
|`slow` |slow traffic |25 % or more, less than 75 %
|`freeFlow` |free flow |≥ 75 %
|`unknown` |status not known |–
|===

[[stupne]]
==== Levels of traffic (NDIC extension)

The NDIC extension states the level of traffic as determined and used in the Czech Republic: the element
`trafficLevel/trafficLevelValue` with the values `level1` to `level5`. The level is calculated
from the ratio of the current speed of the traffic flow to the free-flow speed on the segment:

[cols="1,6,2",options="header"]
|===
|Level |Description |Speed ratio
|1 |individual vehicles only, free flow |85–100 %
|2 |small groups of vehicles, free flow, junctions cleared without problems |75–85 %
|3 |streams of vehicles form, flow is smooth, but speed is lower than the maximum permitted |50–75 %
|4 |queues form, flow is not smooth, average speed markedly reduced, passage through junctions disrupted |20–50 %
|5 |traffic breakdown – vehicles stand or move very slowly in queues |0–20 %
|===

[[kolony]]
==== Queues (NDIC extension)

Segments are internally divided into smaller parts – sections of the Global Network. Congestion is
evaluated on the sections as a drop of the travel speed on the section *below 30 % of the free-flow speed*.
The element `queueInformation` contains values aggregated from the sections of the segment where
congestion was detected; if none was detected, the element is absent. There is at most one per segment.

.Aggregation of individual congestions on a segment
image::kongesce-en.svg[Aggregation of congestion on a segment,width=680,align="center"]

* `queue/queueLength` – sum of the lengths of the sections of the segment (also non-adjacent) where
  congestion was detected [m].
* `queue/fromPoint`, `queue/toPoint` (optional) – start and end of the queue as the distance from the start
  of the segment in the direction of travel, in per cent of the segment length (0–100, at most two decimal
  places):
** the queue starts (`fromPoint`) where vehicles enter it,
** it ends (`toPoint`) where they leave it,
** if there are several separate congestions on the segment, `fromPoint` gives the start of the first one
   and `toPoint` is derived from `queueLength`.

image::poloha-kolony-en.svg[Position of a queue on the segment,width=680,align="center"]

[[rozsireni]]
==== Structure of the NDIC extension

The extension is in a separate namespace `http://ndic.cz/datex2/fcd/extension/1.0` (prefix `ndic`) and is
inserted into the extension point `_trafficStatusExtension` of the class `roa:TrafficStatus`; it applies to all
vehicles. The extension schema `cz-ndic_d2-fcd-extension-1.0.xsd` is part of the specification package
(directory `schema`). Full validation including the extension is possible with the wrapper schema
`cz-ndic_d2-fcd-status-validation.xsd` (it imports the entry schema and the extension schema);
`DATEXII_3_D2Payload.xsd` alone does not check the content of the extension point.

[cols="2,1,4",options="header"]
|===
|Element |Card. |Content
|`ndicFcdExtension/trafficLevel/trafficLevelValue` |0..1 |level of traffic `level1`–`level5`
|`ndicFcdExtension/queueInformation/queue` |0..1 / 1..n |queue on the segment
|`queue/queueLength` |1..1 |total length of congestion on the segment [m]
|`queue/fromPoint` |0..1 |start of the queue from the start of the segment [%]
|`queue/toPoint` |0..1 |end of the queue from the start of the segment [%]
|===

The full description of the extension classes is in the element tables starting at <<el-NdicFcdExtension,`ndic:NdicFcdExtension`>> (chapter XML structure).

[[dostupnost]]
=== Providing available data only

The publication contains only segments for which current data are available at the time of evaluation;
a segment without them is not included. The same applies to vehicle types: the speed of cars or lorries
(together with their free-flow speed) is given only if vehicles of that type passed the segment. A missing
segment must therefore not be interpreted as free flow.

[[platnost]]
=== Time validity and age of data

The publication is updated periodically; `periodDefault` is the length of the period in seconds. The value
`publicationTime` states when the publication was created, not the calculation time. The common
calculation time of all values (end of the measurement and calculation period) is `timeDefault`. No other
validity is used.

.Period and calculation time (sample `fcd-all-lorry-car-sample.xml`)
[source,xml]
----
include::{samplesdir}/fcd-all-lorry-car-sample.xml[tag=timing,indent=0]
----

Each value states in `measurementOrCalculationTime/timeValue` the time of the most recent input used for
its calculation. The inputs are positions of probe vehicles, recalculated at regular intervals to the
sections travelled; the last update of the segment state occurs when the last vehicle leaves it. The
difference between `timeDefault` and `timeValue` is therefore the age of the input data used and a measure
of the system's reaction time.

[[polohy]]
== Location referencing

FCD data are calculated for predefined segments of the road network. A segment may be defined by two
consecutive points of the ALERT-C location table <<ISO14819-3>>, by sections of the Global Network or by
the physical layout of the road.

The format references locations solely in the element `pertinentLocation` (type `loc:LocationByReference`,
`@targetClass` = `loc:PredefinedLocation`) to the set of predefined locations published in the format
`cz-ndic_d2-pls` (set of FCD segments). The recipient looks the location up by its identifier and version.

Segments of the FCD set:

* are sections between two consecutive locations of the Czech ALERT-C location table (table 25); each
  direction of travel is a separate segment,
* the segment identifier is composed of these locations in the form `TS<from>T<to>`, where `<from>` and
  `<to>` are location codes padded with zeros to five digits:
** `TS02125T15781` is the segment from location 2125 to location 15781,
** the opposite direction is `TS15781T02125`,
* the location version corresponds to the network release from which the location set is derived
  (`260601` for network 26.06).

A recipient with the location table can thus identify the segment even without the location set; the full
description (ALERT-C with direction, OpenLR, Global Network sections and the location path) is in the
location set.
